# 反馈、公告与平台设置真实接口验收

日期：2026-11-02（Pacific/Honolulu）。Windows、Java 17、MySQL 8.4 隔离实例、真实 Spring HTTP API、Vite、Chromium。全部账号与业务内容为本地测试数据。

## 已实现范围

- 员工 `/#/feedback`：提交、按状态/内容筛选、分页查询本人反馈、读取培训团队回复。
- 管理 `/#/admin/feedback`：按当前人员数据范围读取反馈、回复与修改回复；版本冲突返回 409。
- 管理 `/#/admin/announcements`：选择当前授权范围内启用且激活的员工，显式确认收件人数后发布。最多 5000 人，名单固定；名单包含越权或失效账号时整次失败。可以查看当前范围阅读人数、撤回公告。
- 员工 `/#/announcements`：读取本人收件列表、查看正文、标为已读。已读由服务器保存，重复操作不改变首次阅读时间。撤回的公告不再显示，不计入未读数量。
- 管理 `/#/admin/settings`：持久化企业名称、培训联系人、可选邮箱和公告未读提示开关。管理员可读，只有超级管理员可写；ALL 数据范围本身不授予设置修改权限。
- 企业名称用于侧栏，培训联系方式用于页脚，未读计数由真实接口读取。账号身份与权限不会因展示配置改变。
- 所有管理写请求进入现有操作审计，不记录正文、密码或令牌。新增 Flyway V14，更新系统时应一起发布前后端和数据库迁移。

## 浏览器实际操作

1. 员工登录，提交“真实接口验收：课程资源建议”；刷新后仍显示本人记录和待处理状态。
2. 超级管理员在真实管理页读取该反馈，回复“已收到建议，我们会在课程中补充操作示例。”；员工再次登录后能看到已回复状态及正文。
3. 管理员在页面选择示例员工，发布“真实公告接口验收”。确认框显示收件 1 人，投递成功。
4. 员工登录后未读提示为 1，打开正文并标为已读；刷新后仍为已读，未读提示消失。管理列表显示 1 / 1 人已读。
5. 管理员修改企业名称、培训联系人与邮箱，刷新后表单仍恢复新值，侧栏和页脚同步展示。员工登录后也读取到相同联系方式。
6. 使用真实 API 构造普通管理员和另一员工，仅用于权限测试夹具。普通管理员拥有 ALL 数据范围，但设置表单禁用、无保存按钮，直接 PUT 设置返回 403。另一员工读取不到原员工的反馈，也未收到此前公告。
7. 管理员通过页面确认撤回公告后，原收件员工再次登录时列表为空，旧公告不再可见。
8. 管理审计实际显示反馈回复、公告发布、设置保存、公告撤回的 SUCCESS，以及普通管理员改设置的 DENIED。
9. 390×844 手机视口检查管理反馈、公告、设置及员工反馈、公告共 5 页，文档宽度均为 390，业务错误区域为 0。公告正文弹窗和设置表单已截图并目视检查；桌面使用 1440×1000。

## 当前限制

- 公告为站内投递，未接入邮件、短信、WebSocket 推送或定时发布。元数据与未读计数在导航时更新，30 秒缓存；公告页刷新和已读操作会强制更新。提醒开关只影响提示，不删除公告或阅读记录。
- 本轮反馈是纯文本通用反馈，类型支持课程提问，但未建立课程关联讨论、评分、附件或多轮会话。
- 公告发布后正文和名单固定，可撤回后重新发布；不会自动发送给之后新增的员工。
- 平台设置只包含展示和联系字段，不配置基础设施、发送凭据或角色权限；没有迁移演示版“恢复演示数据”功能。
- 尚未进行生产上线、并发容量压测、真实手机和多浏览器验收。
