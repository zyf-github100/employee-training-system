# 知行企业培训系统 · 前端第三阶段开发说明

日期：2026-09-14。基于已有 Vue 双端前端，补齐课程章节与资源、精确参训名单、独立题库与组卷工作台。本文记录实际实现、数据规则、验收方式及后端接入边界，格式为 Markdown。

## 1. 交付范围

| 模块 | 本阶段实现 | 员工端联动 |
| --- | --- | --- |
| 课程章节与资源 | 章节新增、排序、删除，正文与时长维护，本机视频/PDF/PPT 附件管理，课程发布检查 | 显示管理员编写的章节和资源，报名、学习、进度与续播沿用员工记录 |
| 参训名单 | 部门筛选、姓名/工号搜索、逐人选择与移出、追加导入 CSV、导出、保存确认 | 精确名单决定培训可见范围，已发布计划自动分配关联的已发布课程 |
| 独立题库 | 单选、多选、判断，题干/答案/解析维护，分类/难度/状态筛选，启停、预览、CSV 导出 | 作为组卷来源，后续修改不影响已组卷题目 |
| 组卷与考试 | 手动选题、分类与难度过滤、按题型数量抽题、分值与顺序编排、草稿、预览、发布 | 按参考人员范围显示考试，支持多题型作答、刷新恢复、计时、按分值判分及答案解析 |

仍为本地前端演示，没有连接 Spring Boot、MySQL、服务端文件存储或真实认证。不得将演示权限、密码、答案、分数或学时用于正式业务；不要录入真实员工信息。

新增四个页面，现有业务页面组件共 18 个。前端路由对员工拦截四个管理入口。非法课程、计划或已冻结试卷的编辑链接显示空状态，不执行写入。路由守卫不构成服务端安全控制。

视觉继续使用深蓝侧栏、青绿主色和白色工作区。章节页采用目录与编辑器双栏；名单页采用候选与已选双栏；组卷页采用选题区与试卷编排栏。小屏改为单列，宽表格仅在内部滚动。

## 3. 课程章节与资源

### 3.1 章节编排

1. 新建课程先保存为草稿，并根据设置的章节数初始化目录。
2. 管理员可编辑章节标题、预计时长及纯文本正文；换行保留，HTML 不执行。
3. 没有任何员工报名的课程，可新增、删除和上下移动章节。
4. 任一员工已报名，包括培训自动分配产生的报名，均锁定章节数量与顺序。
5. 锁定后仍可修改标题、正文、时长、资源。此阶段没有课程内容版本审批。
6. 草稿可暂缺正文；发布时每章必须有正文、视频或 PDF。PPT 原件不能单独满足可学习内容条件。
7. 已发布课程保存时同样校验内容完整性，防止清空整章学习材料。
8. 修改未保存时，站内离页或切换角色会提示确认。取消离页保留内容和当前角色。

锁定原因：第二阶段学习记录用数字章节索引保存完成集合及视频位置。当前采用保守的结构锁定，避免增加或排序后把旧进度归给错误章节。正式课程版本化应改用稳定章节 ID，并记录员工所学版本。

### 3.2 校验规则

| 项目         | 规则                                     |
| ------------ | ---------------------------------------- |
| 章节数       | 1–30                                     |
| 标题         | 1–80 字                                  |
| 单章时长     | 1–240 分钟的整数                         |
| 正文         | 最多 20000 字                            |
| 每章资源     | 最多 10 个                               |
| 视频         | MP4、WebM、Ogg，非空且每个不超过 100 MB  |
| PDF / PPT    | PDF、PPT、PPTX，非空且每个不超过 30 MB   |
| PDF 文件检查 | 校验扩展名和文件头；完整解析由浏览器完成 |
| 保存课程时长 | 自动汇总各章节时长与数量                 |

文件格式检查属于演示输入校验，并不是恶意文件扫描或完整内容鉴定。浏览器不支持的视频编码仍可能播放失败。

### 3.3 本机文件存储

资源不是上传到服务器，而是保存到当前站点来源的 IndexedDB：

- 数据库：`zhixing-training-resources`。
- 对象仓库：`files`。
- 键：资源 UUID；值：文件 Blob/File。
- localStorage 仅保存资源元信息及所属章节，不保存 Base64 大文件。

保存过程：

1. 选择文件后先进行类型、大小等检查，保留在待保存列表。
2. 点击保存，将本次新增文件放入同一 IndexedDB 写事务；事务失败时不更新课程元信息。
3. 文件成功写入后更新课程章节元信息。
4. 清理已移除资源的旧文件；清理失败会单独提示，不回滚已保存内容。
5. 未保存就离开时丢弃内存中的选择，不产生对应资源记录。

IndexedDB 与 localStorage 是两种存储，不能形成跨库原子事务。极端配额或浏览器异常下可能留下无引用文件；正式服务应使用上传暂存、提交关联、定期清理机制。本地业务存储写失败会显示“仅当前页面保留”提示。

### 3.4 员工资源阅读

学习页增加“本章资源”入口：

- 视频：自动读出本机文件，使用原生控件；按员工、课程、章节和文件信息恢复位置。
- PDF：自动读出并交给浏览器内置阅读器；支持下载。
- PPT：仅提供原件下载，明确提示上传转换后的 PDF 才能在线阅读。
- 资源不存在：显示当前浏览器未找到文件的原因及重试按钮。
- 管理员预览不写入员工学习进度；员工需报名后才记录学习。

第二阶段“视频学习”“PDF 讲义”的临时选文件体验仍保留，这类临时选择刷新后需要重新选文件。“本章资源”则在相同来源下可刷新后直接读取。不同浏览器、设备或端口不共享文件；清除站点数据可能永久移除它们。

## 4. 精确参训名单

### 4.1 新旧计划兼容

旧计划没有 `participantIds`，继续按部门或全员范围展示，原完成人数保留为历史演示快照。

打开旧计划名单页，会生成按部门筛选的在职员工建议名单，并明确显示“建议名单待确认”。只有保存后才切换为精确名单。

新计划按目标部门生成初始名单。保存后再修改计划部门，不会覆盖已经确认的个人名单，应通过“参训名单”页面调整。

### 4.2 分配与统计

- 只允许新增在职员工；已在名单但随后被停用的员工可显示并移出。
- 已发布计划至少一名参训员工；草稿允许空名单。
- 保存草稿只保存名单，不生成课程报名。
- 发布计划或保存已发布计划名单，为其中的在职员工分配关联的已发布课程。
- 已报名的课程不重复报名，不重置进度或笔记，不重复累计课程报名人数。
- 移出名单不删除个人学习记录，也不取消其已经获得的课程报名。
- 精确名单优先于部门：跨部门加入的员工能看到计划，同部门但不在名单的员工不能看到该计划。
- 顶部搜索与计划列表使用一致的可见范围。

每人计划进度为关联课程进度的平均值；名单人数取去重后的实际成员数，完成数从成员的实际课程完成状态计算。旧计划在确认名单前仍使用旧快照，切换后的统计可能明显降低，这是统计口径由样例总数变为真实本地记录所致。

### 4.3 CSV 导入导出

导入文件为 UTF-8 CSV，最大 2 MB，1–10000 条记录。支持 BOM、带引号字段及工号大小写归一。

最小模板：

```csv
工号
E20260001
E20260002
```

可选姓名校验：

```csv
工号,姓名
E20260001,林晓
```

规则：

- “工号”表头必需；“姓名”可选，填入时必须与现有员工姓名一致。
- 工号必须已经存在；这里导入的是参训关系，不是创建员工。
- 空工号、不存在、停用员工、姓名不符、列数不匹配都会标记错误。
- 文件内重复以及已在名单的员工会提示并跳过。
- 所有行先检查，任一错误即阻止整批导入，不会部分写入。
- 预览最多 200 条，错误优先；统计与校验覆盖全部行。
- 确认导入只追加到待保存名单，需再次“保存名单”才生效。
- 导出的是当前已选名单，包括未保存的调整；导出字段有工号、姓名、部门、状态与计划完成度。

沿用现有 CSV 的 BOM、双引号转义和公式起始字符防护。

## 5. 题库、组卷与考试

### 5.1 独立题库

题库与考试中的题目副本分离。初始题库由旧试卷按题干去重迁移，并补充多选与判断示例，共 22 题：10 单选、6 多选、6 判断。

字段包括题型、分类、难度、启停状态、题干、选项、正确答案和解析。支持关键词与组合筛选、分页、编辑、预览和 CSV 导出。

停用试题不会参与后续选择和抽题，但不会删除已有试卷或草稿中的题目副本。本阶段不提供题库物理删除和批量题目导入，避免删除影响追溯。

编辑器单选/多选提供四个选项；判断题固定“正确”“错误”。通用校验器允许 2–8 个有效选项，且不允许空项、重复选项或无效答案。多选至少两个正确选项。

### 5.2 组卷工作台

第一部分设置名称、分类、参考部门、时长、及格分和截止日期。

第二部分选择组卷方式：

- 手动选题：按分类、难度、题型和题干筛选，逐题加入；同一题不能重复加入。
- 规则抽题：按当前分类与难度范围，对单选、多选、判断分别指定数量，不重复抽取。
- 抽题不足时说明所需与可用数量，不替换现有试卷。
- 重新抽题会先确认是否替换现有题目和分值。
- 抽题使用前端随机，只服务于演示；正式系统应由服务端抽样并保留规则。

右侧编排题序、删除选题、调整每题整数分值；支持自动分配为总分 100，不能整除的余数分配到前面的题目。人工选题初始每题 10 分，发布前必须调整到 100 分。

### 5.3 草稿与发布

草稿可暂时没有题目，但需具备基本考试名称、时长、及格分和有效日期。草稿保留选中的题目副本、顺序与分值，可从考试管理“组卷草稿”继续编辑；抽题筛选条件和数量目前不单独存为规则历史。

发布检查：

1. 标题 1–80 字。
2. 时长 1–180 分钟，及格分 1–100，均为整数。
3. 截止日期不早于今天。
4. 题量 1–50，每道题有效且 ID 不重复。
5. 每题分值为正整数，总分正好 100。
6. 至少一名在职参考员工。

发布时固定当前参考部门的在职员工 ID，而不是动态随部门变化。发布后的考试题目只读，不能直接回到组卷修改，需创建新试卷。现有代码没有预约发布、审批流或后台调度。

### 5.4 员工答题与判分

- 单选与判断选择一个选项；多选可逐项勾选或取消。
- 全部取消的多选恢复未答状态。
- 多选题全对得分，漏选、多选或错选均得 0 分，不提供部分分。
- 新试卷按分值加总，满分 100；旧试卷没有分值时按等权归一到 100。
- 正式答卷开始时保存题目快照、名称、及格线与绝对截止时间。
- 截止时间取“开始时间 + 考试时长”和“考试截止日结束”中的较早值。
- 刷新后保留答案及截止时间，不重开计时。
- 到时自动交卷；重复提交不再次判分、不覆盖首次提交时间。
- 成绩与解析使用答卷快照，管理员修改题库不会改变旧答卷内容。
- 提交记录按员工隔离；练习不写入正式成绩。

前端包中包含答案，角色及分数均可被修改。这里的快照是业务一致性机制，不是防作弊机制。

## 6. 数据模型与迁移

主键仍为 `zhixing-training-v1`，内部版本升级为 `schemaVersion: 3`。兼容旧存储，不清空既有课程、账号、进度、笔记、评价与考试答卷。

| 对象 | 新增/变化字段 | 用途 |
| --- | --- | --- |
| Course | `chapters?: CourseChapter[]` | 章节结构 |
| CourseChapter | `id,title,duration,content,resources[]` | 稳定目录标识、正文与资源关联 |
| CourseResource | `id,name,type,size,mime,lastModified,createdAt` | 本机文件索引和展示 |
| Plan | `participantIds?,rosterUpdatedAt?` | 精确名单；缺省表示旧部门范围 |
| TrainingData | `questionBank: BankQuestion[]` | 独立题库 |
| BankQuestion | `type,category,difficulty,status` 及题目基础字段 | 题型分类、筛选与启停 |
| Question | `type?,points?,answer:number\|number[]` | 多题型与分值 |
| Exam | `participantIds?,audienceDepartment?,assemblyMode?`；增加“草稿” | 参考范围与组卷状态 |
| Attempt | `questionSnapshot?,passScore?,examTitle?` | 答卷历史一致性 |

旧课程补齐带有明确示例说明的章节正文，原学习索引保留。旧试卷答案兼容数字形式；旧答卷缺失快照时从当前对应试卷补齐。迁移函数只填补缺省字段，不覆盖已有第三阶段内容。

业务变化采用 Vue 批处理后的本地保存，避免批量分配时每添加一个字段都同步序列化整个数据集；离开页面时另作保存。尚不支持跨标签页实时协作或并发版本冲突处理。

恢复演示数据的确认文案已包含资源文件、名单、题库和试卷。确认后重置演示元信息，并按原资源 ID 清理当前已关联的本机文件。不要用此功能处理生产资料。

## 8. 验收记录

在独立的 Playwright 测试浏览器中操作，不清空用户当前预览浏览器的数据。新增测试数据以“QA3”标识。

复验命令：

```powershell
pnpm test:training
pnpm typecheck
pnpm build
```

自动业务检查：23 项通过，覆盖题型判分、抽题唯一性、100 次随机抽样、题量不足、CSV 校验、章节完整性、旧数据迁移、结构锁定、分配去重、角色范围、冻结试卷与幂等交卷。该脚本使用内存仓库，不修改用户浏览器数据。

实际浏览器验证：

- 新增三种题型，保存后刷新可见。
- 手动组三题，保存草稿，再次打开保留题目与分值。
- 总分 30 时发布失败，均分为 34/33/33 后发布成功。
- 修改题库题干，已发布试卷保留原题。
- 员工答题：判断、多选答对，单选答错，实际判分 67；刷新保留多选答案、原截止时间和成绩。
- 规则抽取五题，不重复、总分 100；不足 50 道单选时提示数量且不替换已有选题。
- 新建单章课程，空内容发布被阻止；新增/排序/删除章节正常。
- 无效 PDF 被拒绝；视频与 PDF 保存后刷新可读。

## 9. 后端接入建议

以下为拟议接口，不是已经存在的服务。

| 业务 | 接口建议 | 服务端重点 |
| --- | --- | --- |
| 课程章节 | `GET/PUT /api/admin/courses/{id}/chapters` | 章节版本、引用完整性、编辑冲突 |
| 文件上传 | `POST /api/admin/resources` | 类型/大小/内容校验、对象存储、上传暂存、可访问地址 |
| 文件转换 | `POST /api/admin/resources/{id}/convert` | PPT 转 PDF/图片、队列、转换状态、重试 |
| 参训名单 | `GET/PUT /api/admin/plans/{id}/participants` | 事务、去重、停用人员、历史记录和审计 |
| 名单导入 | `POST /api/admin/plans/{id}/participants/preview` 与提交接口 | 先校验后提交、文件错误报告、幂等键 |
| 题库 | `GET/POST/PUT /api/admin/questions` | 字段校验、题目版本、权限与停用状态 |
| 试卷 | `POST /api/admin/papers`、`POST /api/admin/papers/{id}/publish` | 事务冻结、试题快照、100 分、有效参考范围 |
| 考试开始 | `POST /api/exams/{id}/attempts` | 开考资格、服务端时间、答卷唯一性、返回不带答案的题目 |
| 保存/交卷 | `PUT /api/attempts/{id}/answers`、`POST /api/attempts/{id}/submit` | 截止校验、幂等判分、过期自动提交、答案披露时机 |
| 学习心跳 | `POST /api/learning/{courseId}/heartbeat` | 有效学时与完成条件、断点续播、重复上报 |

前端应增加真正的异步服务适配层，把当前 Store 直接变更替换为请求成功后更新状态，并补齐网络 loading、失败重试与冲突反馈。不能把替换 localStorage 当作已完成后端联调。
