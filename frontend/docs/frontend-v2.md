沿用现有深蓝侧栏、青绿色主色、浅灰背景、白色卡片与 CSS/SVG 封面，不更换框架，不引入额外 UI 依赖。

- `/#/login`：左侧品牌与学习愿景，右侧工号登录/激活/找回三个入口；手机端单列。

- 员工菜单新增“学习记录”“账号与资料”；管理端增加“个人中心”。

基本资料的“保存资料”在未修改时禁用；修改后显示未保存提示。笔记需主动点击“保存学习笔记”，未保存内容离开页面不会自动提交。当前未实现统一的离页草稿保护。

## 3. 演示账号与规则

| 用途         | 工号        | 初始密码/登记邮箱                             |
| ------------ | ----------- | --------------------------------------------- |
| 管理员登录   | `ADMIN`     | `Zhixing@123`                                 |
| 默认员工登录 | `E20260001` | `Zhixing@123`                                 |
| 新员工激活   | `E20260002` | `employee2@zhixing.example`，自行设置演示密码 |

以上是初始值。若已在当前浏览器修改密码/邮箱或激活账号，应使用修改后的信息。示例填入按钮不覆盖已经保存的账号资料。其他在职员工也可以使用管理员名单中的工号与登记邮箱进行本地激活。

规则：

1. 工号去除首尾空格并忽略大小写；在职状态才可激活和登录。
2. 激活仅适用于未激活工号；已激活工号可登录或找回密码。
3. 验证码为 6 位本地演示码，5 分钟有效，60 秒内不能重取；绑定当前工号、邮箱和操作类型。切换操作标签后失效。
4. 新密码长度 8–32 位，包含字母和数字，不允许空白；两次输入必须一致。
5. 修改密码需要原密码，新旧密码不得相同；成功后回到登录页。
6. 激活、重置与修改后的密码不以明文保存。演示实现使用随机盐及 PBKDF2 派生值；初始公开演示密码在源码中。浏览器端派生绝不构成可信认证，正式实现须由后端维护凭据、限流和会话。API 用法参考 [MDN SubtleCrypto.deriveBits](https://developer.mozilla.org/en-US/docs/Web/API/SubtleCrypto/deriveBits)。

## 4. 数据结构与迁移

主存储键保留 `zhixing-training-v1`，内部 `schemaVersion: 2`。复用原键是为了升级时读取旧演示数据，不表示仍使用旧的数据模型。

```text
TrainingData
├── accounts[]                         演示工号、角色、激活状态、密码派生值
├── learning[employeeId][courseId]      报名、学习进度、笔记、视频位置
├── employeeAttempts[employeeId][examId] 考试答卷与提交记录
├── reviews[]                          员工 ID + 课程 ID 对应评价
├── courses / plans / employees        原业务数据保留
└── feedback / notices / settings      原业务数据保留
```

`LearningRecord` 字段：

| 字段             | 类型                   | 含义                       |
| ---------------- | ---------------------- | -------------------------- |
| courseId         | number                 | 课程 ID                    |
| enrolledAt       | ISO 时间字符串         | 报名时间                   |
| lastStudiedAt    | ISO 时间字符串/null    | 最近学习时间               |
| completedAt      | ISO 时间字符串/null    | 首次完成时间               |
| completedLessons | number[]               | 已完成章节索引，去重       |
| progress         | number                 | 0–100 的本地进度           |
| seconds          | number                 | 本地累计秒数               |
| lastChapter      | number                 | 最近章节索引               |
| note             | string                 | 当前员工此课程的笔记       |
| videoPositions   | Record<string, number> | 章节和文件标识对应播放秒数 |

`CourseReview` 包含 `id、courseId、employeeId、rating、content、createdAt、updatedAt`。展示时通过员工 ID 读取当前姓名与头像颜色，不以姓名作为归属判断依据。

迁移策略：

- 保留旧课程、员工、计划、反馈、设置以及已有修改，不清空浏览器数据。
- 旧版单员工进度和答卷迁移到员工 ID 1；新激活员工不继承这些记录。
- 旧 `zhixing-note-{courseId}` 笔记在首次升级时复制到员工 1 的课程记录，包括仅有笔记但进度为 0 的课程。原键不删除。
- 旧进度保留原值；缺少章节明细时按原进度估算已完成章节。因而迁移记录可能出现“4/8 章节、62%”的历史快照，后续完成标记只递增，不倒退。
- 旧版没有准确的报名时间、学习时间和有效时长，所以迁移时间和学时为演示估算，不是实际历史审计记录。
- 迁移可重复执行，不重复报名、不重复评价；仅缺失字段补齐。
- “恢复演示数据”使用干净初始数据，不重新导入旧笔记；需要在设置页二次确认。此操作会重置账号密码、资料、学习、评价及原业务演示数据。

不同浏览器和端口分别存储；当前不做跨标签页冲突解决或跨设备同步。清除浏览器网站数据会丢失本地演示记录。

## 5. 学习与资源处理

### 5.1 报名和进度

仅员工可以报名已发布课程。报名后课程进入本人学习记录，重复报名不会重复增加学习人数。未报名可预览示例内容，但不写入本人学习进度和笔记。管理员预览不写入员工记录。

章节完成使用集合去重，进度按已完成章节比例计算，并保留迁移进度的较大值。首次达到 100% 记录完成时间并开放评价。课程下架后保留已有记录，但不提供继续学习入口。

学习页在文档可见且有焦点时每 5 秒记录一次本地计时；仅在课程内容标签计时，视频还需处于播放状态。后台停留不计入。该实现不验证观看覆盖率，不防挂机、不防拖拽、不作服务端有效学时依据。正式系统必须使用服务端学习会话、事件序号、心跳和完成条件。

### 5.2 本地多媒体

- 视频：`.mp4/.webm/.ogg`，上限 500 MB；实际解码取决于浏览器和视频编码。播放、暂停、全屏等使用原生控件，参考 [MDN video](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Elements/video)。
- PDF：扩展名 `.pdf`，上限 30 MB，并检查 `%PDF-` 文件头；这不是完整文档验证。使用浏览器 PDF 查看器，无法预览时保留下载方式。
- 文件使用 Blob URL，仅本机读取；组件切换资源、章节或卸载时撤销旧 URL。相关生命周期参考 [MDN URL.createObjectURL](https://developer.mozilla.org/en-US/docs/Web/API/URL/createObjectURL_static)。
- 文件二进制不会写入 localStorage。视频位置以员工、课程、章节，以及文件名/大小/最后修改时间区分。文件内容变化或重新导出可能被识别为新文件。
- PPT 当前是 5 页 HTML 课件示例。正式 `.ppt/.pptx` 转 PDF/图片、转码任务、资源权限与签名地址将在后端阶段实现。

### 5.3 记录与评价

学习记录按最近学习时间（未学习则按报名时间）倒序；支持全部/待学习/学习中/已完成、最近 7 天/30 天/全部时间、课程或讲师关键词。分页每页 8 条，CSV 导出当前筛选结果，不只是当前分页。

完成课程后可给 1–5 星并填写 1–500 字评价。每位员工每门课只保留一条，重复提交更新内容及更新时间，保留首次创建时间。详情评分和课程卡片在已有本地评价时使用本地平均评分；无评价时展示初始示例评分。

## 7. 后端接口接入建议（尚未实现）

下表为建议契约，不是已存在的 API。最终以项目根目录开发文档和后端确认后的 OpenAPI 为准。

| 方法和路径 | 目的 | 服务端负责 |
| --- | --- | --- |
| `POST /api/auth/login` | 工号密码登录 | 凭据校验、启停、限流、会话 |
| `POST /api/auth/challenges` | 激活/重置挑战 | 实际投递、有效期、限流、单次消费 |
| `POST /api/auth/activate` | 激活账号 | 员工身份绑定、验证码校验 |
| `POST /api/auth/password/reset` | 找回密码 | 校验挑战、更新凭据、失效旧会话 |
| `GET/PATCH /api/me` | 读取/更新允许的资料字段 | 从会话确定用户、字段白名单、邮箱验证 |
| `PUT /api/me/password` | 修改密码 | 原密码校验、密码策略、会话失效 |
| `POST /api/courses/{id}/enrollments` | 报名 | 课程可用、名额、部门范围、幂等 |
| `GET /api/me/learning-records` | 筛选分页 | 仅本人数据、统一统计口径 |
| `POST /api/learning/sessions` | 学习会话 | 资源授权、服务器时间 |
| `POST /api/learning/sessions/{id}/heartbeats` | 上报学习 | 序号去重、有效观看区间、心跳频率 |
| `PUT /api/me/courses/{id}/note` | 保存笔记 | 字数限制、版本冲突处理 |
| `PUT /api/me/courses/{id}/review` | 创建/修改本人评价 | 完成资格、唯一约束、内容审核 |
| `GET /api/courses/{id}/reviews` | 评价与平均分 | 分页、展示规则、审核状态 |
| `GET /api/resources/{id}/access` | 获取预览资源 | 权限、签名 URL、转换状态 |

接口不得信任客户端传入的 `employeeId` 作为身份依据；应从登录会话取当前员工。列表响应建议统一 `items、total、page、pageSize`；错误响应包含稳定错误码和提示；更新类接口考虑 `version` 与冲突提示。报名、提交与学习心跳需要幂等处理。

接入时需要新增异步请求层，并将当前直接写入 Store 的逻辑改为请求成功后更新本地缓存；补齐加载、失败、重试、401/403、资源转换中、过期链接等状态，不能仅替换 localStorage 就算完成联调。

## 8. 本阶段验证

使用 Playwright 技能规定的 CLI 流程，在独立测试浏览器内操作，未修改用户个人浏览器的数据。除页面截图外，对关键结果读取本地测试存储或导出文件做断言；没有用直接修改存储代替业务流程通过。

已实测：

- 新员工激活，错误登记邮箱和错误验证码被拦截；派生值持久化，无新密码明文。
- 错误密码拒绝、正确密码登录；新员工初始学习记录为空。
- 姓名、电话、简介、头像颜色修改并保存，刷新后仍保留。
- 新员工报名、笔记保存、完成 8 个章节到 100%；默认员工仍为原始 62%，笔记不混用。
- 新建评价、键盘将 5 星调整到 4 星、再次保存，仍只有一条评价；未完成员工不能评价。
- 实际选择 MP4 并播放、暂停、刷新重选后从约 2.15 秒恢复。测试素材为 MDN video 示例，临时文件不随应用发布。
- 非 PDF 内容被拒绝；合法本地 PDF 在浏览器查看器中显示页面、工具栏和下载入口。
- 翻页课件切换后标题与内容变化。
- 学习记录关键词空结果、已完成筛选、真实 CSV 下载，导出内容与本人记录一致。
- 找回密码后旧密码被拒绝，新密码可以登录；个人中心修改密码会退出会话，未登录访问资料页会回到登录页。
- 迁移脚本检查旧课程编辑、62% 进度、仅笔记课程、考试归属、重复迁移幂等及干净重置。

工程与页面检查：

- `pnpm typecheck` 通过；最终 `pnpm build` 通过，生成 `dist/`。
- 生产预览执行 42 组页面/视口检查：管理员 11 页、员工 10 页，分别使用 1440×1000 和 390×844；标题正常、页面无横向溢出、未捕获 JavaScript 异常 0、HTTP 错误 0。宽表格仍允许在自身区域横向滚动。
- 员工直接访问管理员页面被重定向到首页；未登录访问个人中心被重定向到登录页。
- 实际查看了桌面个人中心、翻页课件、PDF 查看器，以及手机学习记录、手机个人中心和登录截图。
- ECharts 分块仍有约 557 kB 的体积警告，不影响构建通过；未将警告隐藏，后续继续评估弱网加载。

截图、导出文件、迁移断言与临时 CLI 脚本位于 `output/playwright/`，已加入 Git 忽略。第一版历史验收保留在 `docs/frontend-qa.md`。

未穷举：验证码时间边界、所有文件大小/编码组合、浏览器存储空间耗尽、跨标签页覆盖、不同浏览器和真实手机硬件、读屏器完整审计。没有进行正式认证安全、服务端并发、防作弊、文件转换或全链路集成测试。
