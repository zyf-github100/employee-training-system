# 员工 Excel 导入与账号激活验收

日期：2026-10-08。真实入口：`/connected.html` → 组织与员工 → 批量导入；员工设置密码：`/#/account-setup`。

## 已交付功能

- 下载含授权部门参考的 XLSX 模板，上传后展示原 Excel 行号、字段和逐行错误，提供可修正后重新上传的报告。
- 单次最多 5,000 行、文件 5 MB、累计解压内容 20 MB。所有业务单元格要求文本格式；不执行公式，拒绝宏、外部工作簿链接、异常压缩包及模板外字段。
- 校验工号格式与重复、姓名、邮箱、电话和有效部门范围；只创建 EMPLOYEE / SELF 的未激活账号。账号没有共享默认密码。
- 预览 30 分钟有效。确认时再次检查工号和权限；有任何错误整批不创建，返回 REVIEW_REQUIRED。相同批次重复提交不重复建号，并发提交同样幂等。
- 最近 10 个本人批次可恢复查看。已提交批次的成员离开管理员权限范围后，阻止继续读取该批次内容或导出激活名单。
- 激活名单仅为仍未激活且启用的账号生成设置码；已激活或停用账号不修改。重新生成会使旧的未使用链接失效。
- 员工列表提供单人激活/重置入口。重置需要界面确认，并立即撤销旧密码及已有会话，员工设置新密码后才能登录。
- 一次性设置码为 32 随机字节，数据库只存 SHA-256 哈希，24 小时有效。完成设置时检查账号版本、状态及签发管理员当前权限，原子消费设置码并保存 BCrypt 密码。
- 不允许重置自己的账号，也不能通过重置停用最后一个可用超级管理员。本人改密仍使用个人资料中的旧密码校验流程。
- 设置码位于 URL 片段中，员工页面读取后清除地址栏参数；也支持通过登录页入口手动输入工号和设置码。无 localStorage 凭据存储。

## 配置与剩余边界

- 新增后端依赖 Apache POI 5.5.1，数据库 V12。接口及环境变量见 `backend/README.md`。
- 正式环境设置 `TRAINING_PUBLIC_WEB_URL` 为员工访问的 HTTP(S) 根地址；未设置时按可信 CORS Origin 生成批次链接。
- 尚无邮件或短信发送，管理员需将各人的链接分别交付。已保留旧的单人 initialPassword 建号方式，尚未统一要求旧账号首次强制改密。
- 未实现批量调岗、批量角色分配和部门负责人。
- 导入预览/历史字段和消耗后的设置码元数据尚无自动清理；需要后续归档策略及导入频率限制。5,000 人导出会占用组织权限变更互斥行，后续高并发场景需专项压测或改成异步任务。
- 审计记录管理写请求、报告导出和账号设置的 HTTP 结果，忽略正文。提交返回 REVIEW_REQUIRED 仍为 HTTP 200，因此审计的 SUCCESS 不代表员工已成功创建。
- 未进行生产部署、多浏览器验收、备份恢复或邮件投递验证。
