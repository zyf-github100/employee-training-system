## 2. 设计方向

- 品牌：知行 ZHIXING，强调企业内部的学习、协作与成长。
- 主色：青绿 `#159A83`；侧栏：深蓝 `#192E3E`；页面底色：`#F4F6F8`。
- 页面组织：固定侧栏、顶部搜索及角色切换、内容标题、核心操作、业务内容。
- 管理端：以统计卡片、图表、列表和表单为主，突出组织培训效率。
- 员工端：以课程插画、学习进度、培训路径和答题体验为主，降低后台表格感。
- 插画：课程封面与首页书本图形由 SVG/CSS 实现，不依赖远程图片和外部字体。
- 响应式：大屏侧栏支持收起，800px 以下使用抽屉导航，600px 以下内容单列；宽表格在自身容器内横向滚动。
- 可访问性：交互使用原生按钮或 Element Plus 控件，补充图标按钮标签、键盘焦点样式、答题选中状态与移动导航展开状态；响应减少动画偏好。尚未进行完整的读屏器审计。

## 4. 已实现的演示交互

### 4.1 课程与学习

课程支持关键词、分类、发布状态筛选，卡片/列表切换和分页。基础设置维护标题、介绍、分类、讲师、封面、必修标记；章节与资源页面维护正文、时长、目录和文件。新建时可设置初始时长与章节数，后续由目录汇总。

新建课程默认草稿；管理员确认发布后才会进入员工课程中心。下架需要确认。必填内容及有效时长、课时在前端校验。

学习页展示管理员维护的章节正文和资源，旧课程正文及 HTML 翻页课件仍标注为示例。员工报名后记录章节集合、进度与笔记，可完成课程并评价。管理员保存的资源存入 IndexedDB，同一浏览器来源刷新后可直接读取与续播；临时选择的文件仍需重选。视频和 PDF 可在线阅读，PPT 只下载原件，不做转换。已有报名锁定章节数量和顺序，避免历史进度错位。

### 4.2 培训计划

计划可选择已发布课程和目标部门、设置起止日期、保存草稿或发布。新计划按部门生成初始名单，随后可逐人调整或 CSV 追加导入；错误行会阻止整批导入。发布计划及保存已发布名单时，为指定在职员工分配关联课程。移出名单不删除既有学习记录。

演示日期场景固定在 2026 年 9 月，不具备生产级状态调度。新计划和已确认名单的旧计划按实际成员与学习记录统计人数、完成率；未确认名单的旧计划保留部门范围和原演示快照。

### 4.3 在线考试

支持单选、多选和判断题。独立题库可筛选、编辑、启停与导出；组卷支持手动挑题和按题型数量随机抽题，设定分值与顺序、保存草稿、预览和发布。发布须有 1–50 道有效题，总分 100，截止日期有效且有在职参考员工。

发布时固定参考人员和试题副本；已发布试卷不允许原地修改。开始考试再保存答卷快照和绝对截止时间，刷新保留答案与计时。新试卷按分值判分，多选全对得分；旧题无分值时等权。超时自动交卷，重复提交不改成绩。模拟练习不写入正式演示成绩。

本地计时、答案和分数均可被浏览器修改，不具有防作弊与权威判分能力。后端阶段必须使用服务端时间、试卷快照、权限和幂等提交。

### 4.4 员工、统计、档案和反馈

员工列表提供部门筛选、姓名/工号/岗位检索、分页、选择、编辑和启停。新增及导入检查工号唯一性；导入使用小于 2 MB 的 UTF-8 CSV，表头必须是 `工号,姓名,部门,岗位,邮箱`。可以先下载模板。批量导入先验证全部记录，再整体写入，错误文件不部分入库。

CSV 导出包含 UTF-8 BOM、引号转义和公式起始字符防护。支持导出课程相关报告、培训计划、员工、部门统计、档案摘要与考试成绩等对应页面提供的内容。证书为明确标注的演示学习证明，下载的是文本证明，不是正式盖章证书。

分析页基于当前示例员工快照进行筛选和聚合；首页学习趋势是标注的样例时间序列。课程分布图统计全平台已发布课程，不随部门筛选改变。

反馈支持员工提交、管理员回复、状态筛选、公告发布及通知已读标记。平台设置可以修改企业名、管理员称呼和联系邮箱，并控制通知红点。

## 6. 数据与存储

为兼容旧版，主存储键仍为 `zhixing-training-v1`，内部 `schemaVersion` 已升级为 3。演示角色、登录状态、员工 ID 分别存于 `zhixing-role`、`zhixing-signed-in`、`zhixing-employee-id`。学习、笔记、视频位置和考试答卷按员工 ID 隔离。旧课程笔记键仅在迁移时读取，原键不删除。默认包含 12 门课程（11 门发布、1 门草稿）、128 名示例员工、6 个部门、6 个计划、3 场测评、3 条反馈和 3 条公告。

浏览器存储禁用时会提示当前更改无法持久化。不同浏览器、不同端口、不同设备不共享数据；不支持多人同时使用和跨标签页实时同步。没有数据库、服务器备份和业务审计日志。

“恢复演示数据”需要用户确认，会恢复账号、演示密码、资料、课程、名单、题库、试卷、员工、学习记录、笔记、评价、答卷、反馈、公告及设置，并按原资源 ID 清理当前关联的本机文件；保留演示角色和登录状态，当前员工重置为初始员工。此操作不重新导入旧笔记。请勿将其作为生产系统数据清理方案。

## 7. 下一阶段：对接 Spring Boot

原始完整需求仍以项目根目录《企业员工培训系统开发文档.md》为准。本阶段主要交付视觉和前端交互，后续按以下顺序接入：

1. 真实认证与权限：工号密码登录、激活、密码重置、个人信息维护、JWT/会话、RBAC、部门数据权限。
2. 异步服务层：在 `services/` 增加真实请求适配，根据已确认接口将当前直接修改 Store 的操作改成请求成功后更新状态；补充 loading、网络失败、重试、空数据和并发冲突处理。不能只替换一个本地存储方法就视为完成接口接入。
3. 课程资源：将已有目录、本机资源与播放器接到对象存储、签名地址、上传校验、PPT 转换、学习心跳及服务端有效学时。
4. 培训计划：将已有精确名单、CSV 预检及课程分配接入服务端事务，增加到期任务、状态流转、审计和冲突处理。
5. 试题和考试：接入已有题库、组卷、快照流程，由服务端隐藏答案、校验参考权限、权威计时、幂等判分，补齐题目及成绩批量导入等能力。
6. 培训档案与证书：真实员工维度学习明细、考试记录、证书颁发和验证、服务端导出与管理监控。
7. 运营：课程评分评价、通知推送、操作审计、异常监控、备份恢复，以及服务端统计口径对齐。
